## Make the file from the script, not by hand

- **A network built in Python goes to the GUI through
  `gui.backend.export.network_to_gui(net, layout=..., labels=..., example=...)`
  (#902).** It maps every supported node and element to its GUI type and data
  keys, picks each edge's handles per node type, writes walls as thermal
  edges and compositions as exact mass fractions. It raises
  `UnsupportedForGUIError` listing anything without a GUI form, rather than
  dropping it.
  - Supported in phase 1: boundaries, plenum, momentum chamber, combustor,
    channel, orifice, pressure loss, lossless connection and thermal wall,
    with smooth surfaces.
  - Not supported yet: impingement arrays, effusion, film, ejectors, tees,
    vortex. Hand-write those, following the next section.
- **A worked example's GUI file is generated by its script**
  (`--write-gui`), and a test pins that the GUI solves to the script's
  numbers and that the shipped file is what the script writes now.
  - Model: `python/examples/papers/hylton1983_c3x_vane.py` with
    `test_paper_examples.py`.
  - The shipped file is never edited by hand.
- **Refusals to expect:**
  - a channel with an explicit convective area (the GUI derives it from the
    geometry);
  - a head-loss correlation whose area differs from its element's (the GUI
    has one `area` field for both: give the element the same area);
  - a static-coupled `PressureBoundary`;
  - an orifice with a non-default `injection_angle_deg`.

## Hand-written files

- **Format.** `{version, example?, nodes, edges, solverSettings?}`. Nodes are
  `{id, type, position: {x, y}, data}`; edges are
  `{id, source, sourceHandle, target, targetHandle, type, data}`. Take an
  existing example as the template, never memory.
- **Handle ids differ by node type, and a wrong one fails silently.**
  - The backend solves an edge by `source` and `target` alone; the canvas
    draws it only between handles the nodes define. So a wrong id solves,
    but the node is DRAWN DISCONNECTED (the C3X cascade inlet, 2026-11-01).
  - Read the ids from `gui/frontend/src/utils/nodeHandles.generated.json`
    (`scripts/gui_node_handles.py`, #901):
    - plenum: `flow-left` (in) and `flow-right` (out), plus `flow-top` and
      `flow-bottom`;
    - lossless connection: no id (`null`);
    - merge chamber side stream: `side-target`;
    - ejector, MPCE tee and effusion liner: `port-*`;
    - most others: `flow-target` / `flow-source`.
  - An edge with no handle id is valid: the canvas uses the first handle on
    that side.
  - On load the GUI moves a wrong positional handle to the first one on that
    side, and reports a wrong named port in the load notice (#901). Do not
    rely on that for shipped files.
- **Walls.** The thermal edge's `data.area` is the contact area. Always set
  it: the schema default is 0.05 m^2. A wall on a plenum or an orifice is
  dropped on load, because they have no surface.
- **Compositions.** `dry_air`, `humid_air` (with `ambient_T`, `ambient_P`,
  `relative_humidity`), `fuel` (CH4), or `custom` with `custom_fractions`
  (`mode` `mass` or `mole`).

## Layout

- **Flow runs left to right.** Supply and inlet boundaries are on the left,
  sinks and exits on the right. Keep the default rotation so edges read
  forwards; rotate a node only to express a real side branch.
- **The main flow path(s) sit on one row, centre-aligned, so the arrows run
  straight** (user, 2026-10-30).
  - Since file version 1.2 (#865), `position` is the card CENTRE, so one `y`
    for the whole row does it, whatever the card heights.
  - In a 1.1 file positions are top-left corners: use y = row - height/2
    per card.
- Branches leave the main row above or below and rejoin to the right.
- **Even spacing:** about 200 px between neighbouring card centres along the
  flow (the examples use 200-300). Never let cards overlap; wide cards
  (arrays, liners) need the larger gap. Keep coordinates on the 10 px snap
  grid.
- Probes and thermal links (walls) sit off the flow row, so their dotted or
  thermal edges do not cross flow edges.
- **A repeated unit (C3X: 19 segments) is one row per unit**, with the coupled
  pair (gas channel and coolant channel) stacked inside the row (+70 px), and
  the wall between them.
  - Shared upstream equipment (compressor exit, burner, inlet plenum) goes in
    a column on the left, at the middle of the rows.
  - Long fan-out edges from one plenum to many rows are fine.

## Solve behaviour to expect on large networks

- **One plenum feeding many near-sonic paths stalls hybr on a cold solve**
  (C3X: 13-29 s per cold solve, against 2-3 s warm). Scripts that solve in an
  outer loop pass `x0` from the last solve; the GUI warm-starts from a prior
  result.
- **The cold-start guess is network-wide** (#899). One small
  `MassFlowBoundary` (a fuel or coolant feed) sets every element's starting
  mass flow, and boundary temperatures are averaged across unrelated
  streams. Near sonic that can land a chamber on its supersonic root: the
  result is demoted, and the outcome is "inconsistent". Until #899 is fixed,
  a cold solve of such a network can be slow or wrong where a warm one is
  fine.

## Check

1. **The GUI's own solve path:** `NetworkRunner.from_dict(doc).solve()`
   (`gui/backend/runner.py`). Report convergence, the outcome message and the
   key results. For an exported network, compare with
   `NetworkSolver(net).solve()`, as `python/tests/test_gui_export.py` does.
2. **Handles:** `python/tests/test_gui_node_handles_sync.py` checks every
   shipped example against the handle table. For any other file, run the same
   check, or load it and read the load notice.
3. **Visual:** load the file in the built GUI in a headless browser
   (Playwright, dev-only, never a package dependency). Screenshot the canvas
   (fit to view) and the Inspector of the important elements.
   - Look for overlap, crossing edges, truncated card rows, flow that reads
     right to left, and a node with no drawn edge.
   - The edge check reports every left/right flow edge whose two handles
     differ in height by more than 0.5 px; a main path must report none.
4. **Round trip:** save (download fallback, or a stubbed picker), load the
   saved file, and compare nodes, edges and solver settings.
5. **Sign-off:** the user's look in the real GUI. The native Save-as dialog
   is never exercised headlessly.
